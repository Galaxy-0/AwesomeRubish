## 完整开录流程（方向短测后再用）

1. **插好USB手柄，先不启动游戏。**

   ```sh
   .venv/bin/python -m rl.demo.controller --out work/rl-demo/controller-check-002
   ```

   **只跟终端当前提示做，不要提前按下一项。** 先平放约3秒；然后逐项按印字ZR/ZL/B/R/A/X/Y/L、
   摇杆按下、−/+、十字键、截图/HOME，再推摇杆四向，最后水平左右转、抬头/低头、左右侧倾。
   每项识别或12秒超时后自动进入下一项；松开按键、摇杆回中，等下一条提示。转到位保持不动，等✓后再恢复正常握姿。
   约2–3分钟，动作慢可加 `--timeout 20`。不覆盖001；若002已存在，改003等新目录。
   最后直接打印结论表，并保存 `report.md`、`summary.json`、`profile.json` 和完整 `samples.jsonl`。
   看每个按键是否识别、绑定是否唯一、摇杆漂移/死区、yaw/pitch/roll的SDL轴与正负。
   原始轴（含trigger 4/5）、全部SDL按钮、原始/处理后摇杆、rad/s陀螺仪均保留。
   普通录制需要 `profile.json` 中 `complete: true`（关键操作通过）；可选未确认键单列且不启用对应组合。游戏画面方向仍需短测，不用猜测左右映射。
   若访问被拒：系统设置→隐私与安全性→输入监控，授权启动工具的终端/App并重开。不要先录一整局才检查轴向。

2. **先开一局脚本预热，再录人玩。** 每次换新的输出目录，不覆盖旧录像。

   ```sh
   .venv/bin/python -m rl.demo.capture --fixture --source script --opponent 52 \
     --host work/rl-demo/ink-recording-host-r1/dmhost-demo \
     --modules work/rl-demo/ink-recording-host-r1/modules \
     --render-predicate async --present-link 0 --max-catchup-frames 1 \
     --ink-every 30 --warm-from work/rl-demo/async-live-full-r1 \
     --out work/rl-demo/my-warm-001
   ```

   正式人玩：把 `--source script` 换成
   `--source controller --controller-profile work/rl-demo/controller-check-002/profile.json --allow-unqualified`，
   `--warm-from` 改成本次预热目录，`--out` 改成 `work/rl-demo/my-demo-001`。
   温泉峡谷180秒，水刀vs.52，双方主武器only，游戏内临时+5/陀螺仪开启。
   窗口完整渲染；异步predicate仅影响录制夹具渲染，正式对战宿主未变。

3. **画面出来先确认轴向和按键。** 按ZR从出生点发射；试移动、转镜头、轻挥/蓄斩、ZL潜墨、B跳跃。
   按**手柄印字**：B=跳跃、ZL=潜墨、ZR=开火、R=副武器/出钩、RS=大招、Y=回正。
   校准只确认物理轴和宿主输入约定；画面正负仍需这次短测。默认0.15径向死区，载入profile后同时校中心。
   确认没有反轴、持续漂移、明显卡顿，再开始有效示范。默认屏蔽R/RS；不要切全装备录阶段1。
   这是数据准备入口，`--allow-unqualified`不代表数据已合格，当前mask和已知缺口仍保留。

4. **换对手：** 下一局将 `--opponent 52` 换成
   `--opponent policy --policy arena/policies/alpha`（或bravo/版本目录）。
   策略对手仍用其水刀8000，**不是.52**；这类录像目前不支持水刀vs.52的BC转换，先单独归档。

5. **结束与保存：** 到Winners自动保存并关闭本局。提前结束用终端Ctrl-C；手柄Minus+Plus仅在两个键均确认后可用，
   或另一个终端 `touch work/rl-demo/my-demo-001/STOP`，部分录像会标取消。
   不要强杀宿主或覆盖输出目录。每局新进程，原存档不写。

6. **找数据：** 指定目录有 `result.json`、`trace.json`、逐帧输入/状态、原始USB输入。
   `result.session` 指向本局原生日志及1600²墨图；`native-ink.json`/`periodic-ink.json`是墨图索引与资格报告。
   墨图每30帧一次，只有已验证地面片区在精确读回帧有效；墙/歧义片区/缺帧仍未知。
   截图、录像、墨图和BC样本都只在私有 `work/`，不提交、不公开发布、不自动训练。

软件输入→呈现延迟不含USB和屏幕响应；开录前性能实测结论见最新run70报告。
