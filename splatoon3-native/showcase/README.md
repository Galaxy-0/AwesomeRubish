本地生成 `showcase/index.html`，由用户私下发布。页面 CSS / JS / 派生地图与回放数据内联，外部依赖为 [cdnjs 固定 three.js 0.160.0](https://cdnjs.com/libraries/three.js/0.160.0)（SRI）和按设计要求加载的 Google Fonts（Barlow Condensed / IBM Plex Sans / IBM Plex Mono）。首次 3D 展示需加载 CDN；字体加载失败时使用系统回退。未加载 WebGL / CDN 时可切到保留的 2D 俯视图。手机可用，支持深浅色。

## 生成和查看

```sh
# 在 splatoon3-native 项目目录；只读已有数据，不启动游戏。
.venv/bin/python showcase/build.py
.venv/bin/python showcase/check.py
# 选择空闲端口；仅本机预览。
.venv/bin/python -m http.server 8873 --bind 127.0.0.1 --directory showcase
```

`build.py` 需要现有 `work/` 数据与项目 numpy 环境。缓存放在 ignored `work/showcase/`，原件不删除；派生数据另写 ignored `showcase/data/derived.json`。最终只需分发 `index.html`，不需要 data / JS / 模板旁文件。

**Git 边界：** `index.html`、data / meshes / traces 及 JSON / NPZ / 模型数据扩展名均已加入本目录 `.gitignore`，不得强行添加。只提交 Python / JS 生成与页面源码、HTML 源模板、说明和检查，以及 GOAL / last 报告。目录中没有游戏纹理、图片、截图、原始网格、音频或二进制。

## 数据方法与边界

地图输入为本地 `work/arena/maps/*/{navigation.json,sight.npz}`。地面按 2 单位粗格重建，只留至少一个出生点可达的最高层；竖直碰撞面投影成 2 单位墙体体素，Y 量化 0.5 单位，装饰墙上限为邻近地面以上 12 单位。输出没有原始三角面 / 拓扑。层叠地面、薄壁、动态物体等有损失，不能当作完整原生碰撞地图。人物穿透显示，保留简化最高层下的回放轨迹，不代表通视。

路线对有向导航图做 Dijkstra，以三维边长除以 S1 P0 实测 AP0 人形满杆速度约 0.096 单位/帧（5.76 单位/秒）。从落地出发，不含发射、加速、转向、跳跃执行、涂墨与战斗损失，仅作静态时间下界。

视域直接调用 `arena.geometry.GeometricVision`：约 10 单位粗采样，各图89/109/109点；眼高1.1，身体射线高.12/.7/1.3，范围100，360°可转身潜在视角。热度是能通视的目标采样占整图样本比例，不是实时敌人可见性、涂地或官方FOV。默认仅展开选中或悬停区域，其余以编号点表示；出生点和角色标签参与统一避让。

伏击候选必须为静态潜在可潜墨地面、5–22单位内覆盖命名要道、站立射线可通达要道，并在指定出生侧接近路线上约18单位处的对手观察位下，低姿态身体三段射线(.12/.25/.35)均被遮挡。此处同样用 GeometricVision + 碰撞射线；假定360°视角，不能靠背对假装遮挡。**实际己墨、出墨时机、弹道体积、对手换路都未验证**，不是实战安全点、飞索挂点或必杀路线。D2等用户指示再测。

武器数值来自 `arena/lib/stamper_data.py` 的 A6 证据；潜墨保蓄原生不支持，飞索部分机制和中路夹具已实测，精确锚点/护甲仍待传感。T1使用R0既有50局与R1–R9 BO3，分清R0 47:3和独立A5 61:9。熟练度卡独立绑定源码哈希；摘要不同时逐字节比较卡片 / 擂台冻结快照的入口、辅助模块及配装，不改策略目录。

S1使用 `work/sim/window-20261021/comparison.json`、`models-v2/motion.json` 和已存 route-check trace。校准有改善，排名反例仍在；保真度未签收，不提供全局AI强弱榜，也不凭空给出 .52 / 精英枪 / 热泡对位结论。

## 视觉设计（2026-10-21）

以“水刀战术板 / 赛前作战简报”为定位。首屏直接展示地图；冷蓝中性色、单一页面强调色、洋红/青绿队伍色。深浅主题同步场景背景、地形、图例与图表；高度底图保持单色阶，战术底图使用半透明覆盖。相机只根据已有派生几何取景，不参与地图分析。窄屏单列，地图上保留紧凑回放栏；尊重 reduced-motion，跟随时关闭平滑追镜。

时间轴上的出刀为记录的 ZR 松键输入；倒下/潜墨刻度来自相邻记录状态的切换，不推断击倒归属。无该事件的片段不补造刻度。图表保留实际纵轴比例，校准预测帧数横轴按30/60/120/300的真实间隔布点，端点标签在右侧避让。

本轮只修改模板、场景/回放展示、资源白名单与说明；`build.py`、`derive_3d.py`、`derive_traces.py`保持字节不变。对照修改前快照，除展示源码哈希外，内联派生数值逐值相同。自查与截图在ignored `work/showcase/d1-design-*`，不提交。

## D2成果接入（2026-10-21，步骤A）

`zipcaster.py`只从已有D2紧凑层挑展示点，不重算碰撞/视域。每个命名目标区域按现有几何连招条件、落地潜在视域、距离排序，3u内去重，最多8点；三图保留26/27/28点（跨目标去重后），完整818/1327/1035候选仍留原件。支持目标区域与蓄斩+轻斩/炸弹组合筛选。95伤害组合显示不足满血击倒；130只作为算术和落点范围候选，明确大招内炸弹输入未验证。

实心标记是**原生已验证人物挂墙姿态**，不是已读出的精确锚点；目前仅温泉中路夹具1处。空心环是待验证静态候选，穿透显示且不代表通视。点击候选或侧栏选择器查看条件与参考连线；选择普通地面/区域/伏击点会返回原有站位检查器。原生连招按钮切换到实测片段、筛中路105组合并跟随人物；不自动播放或重跑游戏。

机制卡包含松R起飞、35–37u范围口径、约65u/s分段峰速、大招内20/21帧35/70、挂墙受伤、倒下不回SP起点及96帧回程观测窗口@QS57AP。保留样本与观测阈值，未把它们写成普适精确极限。当前构建<1MB，硬限制<10MB；只有选段/数值内联，无新外部依赖。D1既有地图、武器、故事、校准和四段trace逐值保持。

运行`build.py`前需本轮D2的`showcase/data/zipcaster-{layer,traces}.json`、`work/d2/measurements.json`和数值证据报告。`check.py`追加逐原件复算连招与每区域数量限制。B的只读原生传感不属于此页面步骤，本轮未启动游戏。
