## 第二阶段：可解释策略擂台（2026-10-18 对齐，替代"先上 RL"）

目标：不做强化学习为主。两个 Codex 会话各写一份**可解释的 Python 策略**（规则/状态机），在 1v1 擂台上批量对打，用胜率与复盘研究配装、地图立回。RL 以后只用来探索"奇招"。

已定决策：
- **信息有限**：策略只拿到真人能拿到的信息——对手在视线内（未被遮挡、未潜墨）才给准确位置，否则只给最后一次看见的位置与时间，以及踩到敌墨、被标记等信号。
- **公共技能库**：擂台提供双方共用、双方可见的基础函数（寻路走到某点、瞄准某点、潜墨游到某点、读某处墨色、模式目标位置）。策略只比战术。
- **同武器**：双方都用工作刮水刀（Splatana Stamper）。
- **配装属于策略**：每份策略在自己的配置里声明主/副装备技能，擂台按声明设置。
- **范围**：先占地对战 + 3～5 张结构不同的地图（含温泉峡谷）；之后逐个加入区域、塔楼、鱼虎、蛤蜊，每加一个模式补该模式目标的状态读取与测试。
- **互不可见**：两个策略会话看不到对方代码，只能看对局记录与截图。擂台由 Claude 调度，策略会话之间不直接交流。
- **有效门槛**：每局交换出生点与阵营；按二项检验给 95% 双侧精确区间，下限 > 50% 才算更强（70 个有胜负结果需 ≥44 胜；以后 T1 每轮100局需 ≥61 胜）。

### A7 对战吞吐提速（2026-10-20，用户：优先提高对战速度，T1 暂停期间做）
现状：一局约 20 分钟墙钟 = 约 9 分钟起机/建房/加载 + 约 10.5 分钟受控对战（游戏内 3 分钟，受控比实时慢约 3.5 倍，GPU 是瓶颈）；一轮 BO3 + 输方 6 局单房自测 ≈ 2 小时。
目标：一局（含开局）墙钟 ≤ 8 分钟；BO3 一轮 ≤ 10 分钟；结果不变（同样的 fixed60 时间语义、同样的可见性/沙箱/判定规则）。
1. **进程复用 / 连续开局**：一局结算后游戏进程不退出，回到私房直接开下一局（换图、换边、换策略快照均可），省掉每局的起机与加载；房间异常时才重建。给 t1_round、test_a5、proficiency 都用上。
2. **降渲染开销提速**：在不影响判定的前提下降低内部渲染成本（更低内部分辨率、跳过对判定无用的后处理/特效/阴影等），测受控帧率提升；涂地判定若依赖 GPU，必须验证比分不变（同输入对照）。
3. **并行度**：重新测 4/5/6 房的稳定性与总吞吐（局/小时），给出推荐值。
4. T1 规则配套：输方自测允许最多 3 房并行。
验收：自动测试 + 前后对照表（每局墙钟、受控帧率、局/小时）+ A5 比分一致性回归；commit + push。

- 正式对局中若新版本报错或超时，该局判该版本负，并把错误日志写进战报交给作者（不作 void）。
