# 示范录制准备：链路通过，实时60与BC真实性未达标

实验始于2026-10-23，2026-10-24收尾。本轮只准备录制，不训练。脚本控制的原生整局已到双方Winners，保存和近似转换跑通；**尚不是可交给用户正式录示范的合格工具**。主要未闭合项为实时60fps、物理手柄方向/按键确认、原生全图墨色与完整武器/弹体状态。没有用慢放替代实时速度，没有开始BC或RL，没有恢复T1/S1。

数值汇总：[rl-demo-20261023.json](rl-demo-20261023.json)。操作说明：[rl/demo/README.md](../rl/demo/README.md)。原始实验均在本机`work/rl-demo/`保留，不提交。

## USB手柄

在本机实际打开Nintendo Switch Pro Controller（VID057e/PID2009），使用已有SDL2 HIDAPI驱动，USB握手/全量报告/IMU开启由SDL完成，没有下载依赖。独立工具`python -m rl.demo.controller`实时打印摇杆、按键、陀螺仪和时间戳。3.0025秒自检得到627个传感事件，按事件时间戳测得200Hz；209次“最新报告”更新约66.67Hz，三子样本成批到达，不能把轮询约792Hz冒称传感采样率。

SDL陀螺仪单位rad/s，宿主输入为turns/s，除以2π。当前映射`SDL(x,y,z) → native(x,-z,y)`为待人工核验的坐标约定，未把静置噪声当作用户转动。自检中未观察到按键变化，物理按键映射和转动正负仍须用户实际操作确认。原始轴/按钮/IMU保存，默认不另加软件摇杆死区；诊断可指定`--deadzone .15`。私有demo传输支持±8turns/s，陀螺仪不再错误地按摇杆±1截断。

本轮没有遇到输入监控权限拒绝。如设备不可访问，用户可到“系统设置→隐私与安全性→输入监控”允许启动脚本的终端/App，再退出重开。没有要求或修改其他权限。

原件：`work/rl-demo/controller-r1`、`controller-r2`、`controller-final-r3`。尚未进行真人控制的完整录制。

新增代码全部在`rl/demo/`。构建器基于本地阶段0诊断构建生成另一路径的宿主，不覆盖默认二进制。当前宿主`work/rl-demo/host-r5/dmhost-demo`，SHA256 `32b5b3e5e9243732713eaae3b2be99cc60fcc37b2cac86cc590f9de38516914f`。必须显式启用`DM_TEST_DEMO`；正式arena/T1/proficiency及常规native入口拒绝该标志或demo宿主身份。直接瞄准文件/开关被拒绝，原生计数也确认双方直接瞄准写入为0。

一房双进程，温泉峡谷，工作刮水刀8000对.52（ID50），180秒涂地，默认屏蔽R/RS，仅主武器。灵敏度+5/陀螺仪开启仅写进程临时选项，原存档不改。人玩窗口原生720p完整渲染；A8减绘仅用于headless对手，人玩侧减绘计数0。`pixels=False`只省RPC小图readback，不关闭实际窗口。

每局自动保存并关闭自建进程；Ctrl-C、Minus+Plus或输出目录的STOP文件可中断并标部分局。启动阶段也有取消和资源停滞保护。本轮没有启动第二个并行房间。

## 实时性逐项尝试

暖机排除前600帧，比赛期最多取到10800帧。逻辑间隔来自逐present ACK墙钟，上屏时间来自Metal drawable的`presentedTime`。1% low定义为最慢1%间隔的均值取倒数。上屏只统计相邻原生帧且均有正presentedTime的样本；遮挡/丢弃的0时间戳单列，绝不跨缺口推断帧率。以下是条件性帧率，不能认证连续显示60。

| 配置 / 私有目录 | 逻辑中位 / 1% low fps | 上屏中位 / 1% low fps | 软件输入→上屏P50 / P95 ms |
|---|---:|---:|---:|
| 去冗余诊断，两端完整，link1 / perf-lean-r4 | 36.96 / 15.59 | 30.00 / 15.00 | 83.66 / 91.96 |
| 人玩完整、headless对手A8，link1 / perf-peer-r5 | 39.36 / 15.56 | 30.00 / 14.40 | 82.89 / 91.52 |
| 同上，link0 / smoke-link0-r7（历史尾部失败） | 36.97 / 5.70 | 40.00 / 13.01 | 45.89 / 51.08 |
| 最终完整局，link0 / smoke-final-r11 | 39.11 / 15.31 | 40.00 / 14.66 | 45.47 / 50.27 |

r7有7076个0呈现时间戳，存在窗口遮挡/焦点影响，其显示数据仅对有效片段成立，且结算驱动失败，不作完整局证据。最终r11为4个0时间戳，比赛暖机段逻辑平均38.14fps。配置间还存在导航修复/缓存差异，表格是各次测量，不把所有差值归因于单一开关。

延迟是**软件提交输入帧→对应drawable实际上屏回调**，经native frame对齐；不是物理USB按键→屏幕光子的延迟。没有真人按键、摄像机或光电测量。最终P50 45.47ms/P95 50.27ms/最大153.83ms；用户要求的物理端到端输入延迟仍未测得。

按用户提出的降画质方向逐项检查：

| 项目 | 实际结果 |
|---|---|

| 降输出分辨率 | 请求DM_GAME_RES800x450，原生仍输出1280x720；未确认内部缩放，perf-half-r3按请求不符退出，不作有效性能对照 |
| 阴影/后期/AA/UI/特效关闭 | 通用FXAA/bloom匹配键不在已知Splatoon shader表，未定位可合格关闭项；未擅自删除判定消费的pass，不能宣称已经关闭 |

| 着色器缓存 | 使用本地已有缓存，暖机数据新PSO/library计数P95为0，但仍有少量新编译；没有证明全图全动作预热覆盖 |

当前最好可完整复测的方案约38fps平均、39fps逻辑中位，**不存在已经证明稳定60fps的配置**。最终profile人玩侧提交CPU中位3.454ms、提交墙钟23.254ms、GPU活跃10.224ms；对手侧2.703/21.205/8.939ms。drawable等待人玩侧中位0.029ms，普通主循环CPU中位3.769ms。GPU提交/同步、双进程调度值得进一步定位；这些重叠计时不可简单相加或精确归因为某一pass，不足以声称只有CPU或只有GPU瓶颈。

整段原生session（含起机/结算）GPU利用率平均76.93%，进程RSS合计峰值3356MiB、footprint合计6119MiB、新增swapout 0、pressure最大1；不把RSS冒作GPU显存。进一步提速选项是定位本构建原生RenderConfig/内部目标尺寸，或优化提交/同步；本轮未实现，且不会把慢放当解决方案。

## 转换与量化误差

`rl.demo.convert`逐帧驱动同一`rl/gpu/ParallelEnv`物理实现，本机M1用CPU运行；本轮未连接asuka0或开启CUDA远端任务。只省略无用step返回值的观测构建，12帧控制对照state/shots/paint/步数/终止逐项完全相同。

最终`work/rl-demo/bc-final-r11/`导出5316个样本、21个NPZ分片，默认每2帧决策，从双方首次可对照地面帧166至原生比赛结束10799帧；出生飞行与赛后动画明确排除。所有分片有限值、ZR/ZL toggle还原物理电平完全一致；screen为18×32×4，未导出原始referee状态给actor。源状态valid不等于墨色/弹体重建真实。
